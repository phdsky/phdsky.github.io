VectorMapNet: End-to-end Vectorized HD Map Learning

2023年07月23日

Task: End-to-end Vectorized HD Map Learning
Method: DETR-style Element Detection + Autoregressive Polyline Generation
Venue: ICML
Year: 2023
Paper: https://arxiv.org/abs/2206.08920
Code: https://github.com/Mrmoore98/VectorMapNet_code

1. 摘要

VectorMapNet 是首个真正端到端输出矢量化高精地图的方法。HDMapNet 等前驱仍走”BEV 分割 + 后处理（DBSCAN + 贪心连接）”路线，矢量化质量受聚类启发式制约；而 VectorMapNet 把整张本地地图建模为一组多边形元素，每个元素由”类别 + 一组关键点 + 一条折线”刻画，并用两阶段架构直接预测：先用 DETR 风格的 element detector 检测出每个元素的关键点集合，再用一个自回归 polyline generator 在离散化的 BEV 坐标上逐顶点生成完整折线。在 nuScenes 上以多模态融合达到 mAP 52.3%，比 HDMapNet Fusion 高出 14.2 mAP，确立了”端到端矢量化”的新范式，是 MapTR / MapTRv2 的直接前身。

核心论点：HD 地图的本质是矢量集合而不是栅格，模型应该直接学习矢量空间上的分布，把”分割→后处理”换成”检测→生成”。

2. 问题与动机

方案 输出 问题
HDMapNet 栅格 + 启发式向量化 DBSCAN 聚类不稳定；同类邻近元素易错合
LaneGAP / 早期车道线方法 仅车道线 元素类型单一，无法覆盖人行横道 / 边界
离线 HD 地图人工标注 标准矢量 无法在线生成

核心痛点：HDMapNet 的栅格表示决定了它必须依赖后处理来矢量化，而后处理一旦失败，前面所有像素级分割都白做。需要一种把”矢量”作为一等公民的模型表示。

3. 核心洞察

洞察 1：跳过栅格中介，直接对矢量空间建模

去掉中间的栅格 + 启发式后处理，整个矢量化是端到端可学习、可微的。这种”绕过中间表示”的思路与 DETR 当年绕过 NMS 极其相似。

洞察 2：用关键点集合表示一个矢量元素，最简关键点最好

矢量元素如何 query？论文比较了三种几何表示：

表示 关键点数 mAP (Chamfer, camera-only)
Bounding Box (左上 / 右下) 2 40.9
Start-Middle-End 3 32.5
Extreme Points 4 33.6

最简的 bbox 两点表示反而最好：少一个点，预测稳定性反而更高，给后续 polyline generator 留出更多空间去描述细节。这是一条非常工程化的洞察——粗位置预测越简单越好，精细形状交给生成器。

洞察 3：把”形状回归”换成”离散自回归生成”

折线形状的复杂度（曲率突变、自交、回环）让连续坐标回归非常难收敛。VectorMapNet 把 BEV 坐标离散为 200×100 网格（0.3 m 量化），polyline generator 是一个标准的 Transformer，逐顶点输出离散 token，并以 keypoint 作为 prompt：

其中每个 是 200×100 个离散位置中的一个 token，外加结束符。离散化 + 自回归比连续回归在 Fréchet mAP 上从 41.9% 提升到 50.4%，是一次结构性收益。

三个洞察的递进关系

  1. 表示：用矢量集合替代栅格；
  2. 接口：用关键点 query 锚定每个元素的粗位置；
  3. 解码：用离散自回归生成完整形状。

三个关键数字：

  • Fusion mAP 52.3%（fine-tune） vs HDMapNet Fusion 31.0%：+14.2 mAP 的端到端跃迁；
  • Bbox 关键点（k=2）40.9% mAP：最简表示反而最优；
  • 离散自回归 50.4% Fréchet mAP vs 连续回归 41.9%：把形状回归改造成 token 生成的纯收益。

4.2 关键组件

组件 作用 关键设计
Camera backbone 多视角图像特征 ResNet-50 + FPN
IPM (4 planes) PV → BEV 在 −1 / 0 / 1 / 2 m 四个高度面分别做 IPM 并拼接，弥补单平面假设的不足
LiDAR backbone LiDAR BEV 特征 PointPillars
BEV fusion 多模态融合 concat + conv
Element Detector 检测元素粗位置 100 queries，每条预测 (class, k 个 keypoints)
Polyline Generator 生成精细折线 Transformer，离散 200×100 token，自回归

损失函数：

  • ：DETR 风格的 set loss（class CE + keypoint L1，匈牙利匹配）；
  • ：polyline token 的交叉熵（teacher forcing 训练）。

4.3 关键设计：4-plane IPM

单平面 IPM 假设地面是 的水平面，远处误差大。VectorMapNet 在 m 各做一次 IPM，把四个 BEV 特征沿通道拼接，让网络自己挑选合适的高度——以”代价低 + 几何先验”的方式部分弥补 IPM 的不足。这是工程上一个非常划算的小改动。

5. 实验与分析

5.1 主要结果

nuScenes 验证集，mAP（Chamfer 距离 {0.5, 1.0, 1.5} m，单位 %）：

方法 模态 Divider Ped Crossing Boundary mAP
HDMapNet (Cam) C 21.7 14.4 33.0 23.0
HDMapNet (Fusion) C+L 28.3 20.7 44.5 31.0
VectorMapNet (Cam) C 47.3 36.1 39.3 40.9
VectorMapNet (Fusion, fine-tune) C+L 60.1 48.7 48.0 52.3

关键发现：

  1. 端到端矢量化把 Fusion 从 31.0 mAP 抬到 52.3 mAP，绝对提升 +14.2 mAP；
  2. 即便是 camera-only 也能超越 HDMapNet Fusion（40.9 > 31.0），证明范式而非模态是关键变量；
  3. Divider 类提升最大（+31.8 mAP），因为长直线最适合关键点 + 自回归的表示。

5.2 消融实验：验证三个洞察

配置 关键现象 验证洞察
端到端 vs 栅格 + 后处理 baseline 提升 +14.2 mAP（Fusion） 洞察 1
关键点表示：Bbox(k=2) 40.9 / SME(k=3) 32.5 / Extreme(k=4) 33.6 最简 bbox 表示最优 洞察 2
形状解码：连续回归 41.9 / 离散自回归 50.4（Fréchet mAP） 离散 token 显著优于连续坐标 洞察 3
IPM planes：1 plane / 4 planes 4 平面 BEV 特征更鲁棒 洞察 1

注：连续回归 vs 离散自回归的对比为 Fréchet 距离 mAP，论文用其衡量形状质量（Chamfer 不能完全反映顶点顺序）。

5.3 性能瓶颈分析

  • 自回归推理是逐点串行：每条折线 N 个 token 就 N 步 forward，长 boundary 类显著拖慢推理；
  • 2 阶段特征断层：keypoint detector 的 BEV 特征与 polyline generator 的 BEV 特征在训练时未充分共享，可能存在不一致；
  • 离散网格分辨率与精度的折中：0.3 m 量化对车道线已经够，但路口曲率突变区域会有”阶梯”；
  • 训练资源较高：8 × RTX 3090，110 epochs。

5.4 失效场景分析

论文与开源 issue 中讨论的典型失败模式：

  • 复杂路口：当一个区域内有多条交错的车道线时，element detector 可能把两条线的 keypoint 错配；
  • 远距离目标：BEV 特征远端稀疏，生成器容易在 token 序列后段”跑偏”；
  • 时序不一致：单帧推理，相邻帧之间生成的 polyline 不严格一致，需要外部时序滤波。

6.2 复现要点

  1. 关键点表示一定要先用 bbox(k=2) 跑通，再考虑增加点数；
  2. 离散网格的步长要与 BEV 范围匹配——0.3 m × 100 列正好对应 ±15 m，改范围必须同步改 token vocab；
  3. polyline generator 的 EOS token 训练样本要充分，否则推理时长度发散；
  4. 匈牙利匹配中 keypoint 距离的权重比 class 权重更敏感，调高 keypoint 权重通常更稳；
  5. fine-tune 阶段先冻 backbone 再训 generator，可以避免梯度冲突。

6.3 性能优化方向

精度提升

  • 把 IPM 替换成 deformable attention 或 LSS 风格的可微 lift，缓解远端 BEV 稀疏；
  • 为 generator 引入时序记忆（参考 StreamPETR 的滑动 query），消除帧间不一致；
  • 让 element detector 与 polyline generator 共享同一套 BEV decoder（MapTR 走的就是这条路）。

速度优化

  • 把自回归 generator 改为并行解码（parallel decoding，类似 MaskFormer / MapTR 的 instance polyline query）；
  • 这正是 MapTR 的核心改进——一次性预测固定点数的 polyline，整体 FPS 翻倍以上。

7. 研究启示

7.1 可迁移的思想

  • “检测 + 生成”两阶段范式：粗位置用 set prediction、细形状用自回归，可推广到任意”元素 + 形状”的结构化预测任务；
  • 离散化 + 自回归：当目标空间有长尾、自交、突变时，把回归转成 token 分类是稳定的工程选择（与 PointE / Pix2Seq 思路一致）；
  • 最简关键点表示：少即是多——bbox(k=2) 反胜于 SME(k=3) / Extreme(k=4)，是反直觉但有用的观察；
  • 多平面 IPM：用 4 个高度面拼接补 IPM 的不足，是低成本提升 BEV 几何鲁棒性的小技巧。

7.2 方法局限

  1. 自回归 generator 推理慢，长 boundary 元素是瓶颈；
  2. 两阶段架构在训练端有特征不共享的隐患；
  3. 单帧、无时序，对帧间一致性无显式建模；
  4. 离散 token 的精度上限受网格步长限制。

7.3 技术影响

  • 是矢量化建图的端到端范式起点，从此之后矢量化建图论文基本不再讨论”DBSCAN + 启发式连接”；
  • 直接催生 MapTR：把”检测 + 自回归生成”压缩为”polyline query 一次性并行预测”，速度提升一个数量级；
  • 也启发 MapTRv2、PivotNet 等后续工作在矢量表示上做更多尝试（pivot 点、解耦形状与位置等）；
  • 在范式层面验证了”用 DETR-style query 操控 BEV 任务”的普适性，与 BEVFormer / Sparse4D 等共同构成 BEV+Transformer 的方法学版图。
