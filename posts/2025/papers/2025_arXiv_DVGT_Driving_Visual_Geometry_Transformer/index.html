DVGT: Driving Visual Geometry Transformer

2025年12月18日

Task: Driving Dense Geometry Perception
Method: Driving Visual Geometry Transformer, Dense Point Map, Ego Pose Estimation
Venue: arXiv
Year: 2025
Paper: https://arxiv.org/abs/2512.16919
Code: https://github.com/wzzheng/DVGT

1. 摘要

DVGT 是面向自动驾驶场景的 dense geometry perception 模型。它从未给定位姿的多视角驾驶图像序列中，重建第一帧 ego 坐标系下的全局稠密 3D point map，并估计每帧 ego pose。

和传统依赖精确相机参数或外部传感器对齐的方法不同，DVGT 强调直接从图像序列预测 metric-scaled geometry，适配不同场景和相机配置。它把 VGGT 式的通用视觉几何能力推进到驾驶场景：输入不再只是任意多视图图像，而是多相机、多帧、动态道路环境。

DVGT 抛出的核心问题是：自动驾驶是否可以在 object boxes / BEV features 之外，直接学习一个 dense metric geometry 中间表示？

核心论点：驾驶系统需要的不只是“检测到哪些物体”，还需要真实尺度的 3D 空间结构；DVGT 尝试把 dense geometry 变成自动驾驶视觉感知的一等表示。

2. 问题与动机

自动驾驶视觉感知长期围绕 BEV、object query 和 occupancy 展开，但 dense metric geometry 仍然缺少面向驾驶的统一模型。

表示 优点 几何缺口
Object boxes 稀疏、贴近检测和预测 丢失表面、free space、未知障碍细节
BEV features 统一空间，便于多任务 高度、点级结构和真实尺度可能被压缩
Occupancy 表达空间占用 分辨率有限，几何表面不够细
Dense point map 直接表达度量 3D 结构 计算和时序建模更难

通用重建模型通常不是为多相机驾驶序列设计，传统驾驶系统又往往把几何压缩为 boxes 或 BEV features。DVGT 的目标是在两者之间补上驾驶视觉几何底座。

3. 核心洞察

洞察 1：驾驶几何需要跨视角和跨时间共同建模

单帧多视角只能提供空间关系，多帧序列还包含 ego motion 和动态线索。DVGT 同时使用 cross-view spatial attention 和 cross-frame temporal attention。

这对应驾驶几何的两个基本维度：

  • cross-view：不同相机如何共同观察同一个三维世界；
  • cross-frame：同一个世界如何随自车运动和场景动态变化。

只有两者结合，模型才可能从环视相机序列中恢复稳定几何。

洞察 2：直接预测 metric point map 可以减少后处理

模型直接输出 metric-scaled geometry，不依赖外部传感器后对齐。这使它更接近一个端到端几何感知模块。

这点对自动驾驶很重要：如果几何结果需要大量后处理或外部传感器补齐，它就很难作为轻量中间表示进入端到端系统。DVGT 的目标是让 dense point map 本身成为网络输出。

洞察 3：相机配置不应被写死在模型里

DVGT 不显式依赖固定 3D geometric priors，因此能处理不同 camera configurations。

量产车队中相机布局、视场角和安装位置可能不同。一个过度依赖固定相机配置的方法，跨车型迁移会很困难；DVGT 希望通过视觉特征和注意力机制学习更通用的几何关系。

4. 方法设计

4.1 整体架构

unposed multi-view image sequence
        │
        ▼
DINO visual backbone
        │
        ▼
intra-view local attention
        │
        ▼
cross-view spatial attention
        │
        ▼
cross-frame temporal attention
        │
        ├── global dense point map
        └── ego poses

4.2 关键组件

模块 作用
DINO backbone 提取鲁棒视觉特征
Intra-view local attention 建模单图局部几何
Cross-view spatial attention 建模多相机空间关系
Cross-frame temporal attention 建模时间连续性和 ego motion
多头输出 解码全局 point map 与 ego poses

4.3 与 BEV / Occupancy 的关系

DVGT 不是 BEV 感知的简单替代，而是提供另一种中间表示。

路线 中间表示 更擅长
BEV-centric 鸟瞰特征图 多任务共享、检测、地图
Occupancy-centric 空间占用格 free / occupied / unknown
Geometry-centric dense point map + ego pose metric 3D grounding、表面与空间结构

真正的系统可能不是三选一，而是把 dense geometry 用作 BEV / occupancy / planning 的 grounding。

5. 实验与分析

论文在 nuScenes、OpenScene、Waymo、KITTI、DDAD 等驾驶数据混合训练，并报告在多场景上优于已有模型。这里保留核心实验结论：DVGT 的评估重点不是检测 mAP，而是 metric geometry 是否能在驾驶场景中泛化。

实验评价的关键对象是：

评价对象 说明
Dense point map 是否恢复真实尺度 3D 结构
Ego pose 是否理解自车运动
Cross-dataset generalization 是否适配不同驾驶数据分布

这和常规 BEV 检测论文不同：DVGT 的价值不是立刻提高规划分数，而是提供更可靠的几何底座。

三个关键数字：

  • 5 个数据源：nuScenes、OpenScene、Waymo、KITTI、DDAD。
  • 3 类注意力：intra-view、cross-view、cross-frame。
  • 2 类主输出：dense point map 与 ego poses。

6. 工程实践

DVGT 适合放在自动驾驶几何分支中，为后续 occupancy、planning 或 object grounding 提供度量几何输入。工程落地时需要关注：

  • 实时性：dense point map 比 sparse query 更重；
  • 动态物体区域：动态对象会破坏静态重建假设；
  • 相机掉线：环视系统缺少某一路输入时几何是否稳定；
  • 尺度一致性：多数据集训练时 metric scale 是否保持一致；
  • 下游接口：point map 如何变成 occupancy、cost map 或 planning feature。

7. 研究启示

DVGT 的意义在于把 VGGT 式通用几何模型推进到驾驶场景。它说明自动驾驶中的 dense geometry 不只是离线重建问题，也可以成为在线感知和规划链路中的中间表示。

但 DVGT 本身更偏感知几何，还没有完全解决在线规划问题。这个缺口正是 DVGT-2 要补的：把 dense geometry 从 batch 重建推进到 streaming planning。
