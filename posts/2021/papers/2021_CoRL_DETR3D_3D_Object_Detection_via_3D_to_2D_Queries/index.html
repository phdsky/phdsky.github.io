DETR3D: 3D Object Detection from Multi-view Images via 3D-to-2D Queries

2021年11月08日

Task: Multi-view 3D Object Detection
Method: 3D-to-2D Object Query, Backward Projection, Set Prediction
Venue: CoRL
Year: 2021
Paper: https://arxiv.org/abs/2110.06922
Code: https://github.com/WangYueFt/detr3d

1. 摘要

DETR3D 提出了一种面向多相机 3D 目标检测的统一框架。区别于”先单目预测 3D 框再做后处理”或”先估深度再做点云检测”两类传统方案，本文直接在 3D 空间中操作预测：模型先用 ResNet + FPN 提取每个相机的 2D 特征，再用一组稀疏的 3D object query 反向投影到所有相机视图、通过双线性插值采样图像特征，并在 query 之间用 multi-head attention 进行交互；最终以 DETR 风格的 set-to-set loss 进行端到端训练，不需要任何 NMS。这种自顶向下的范式避开了 depth 预测带来的级联误差，在 nuScenes 数据集上取得了当时 SOTA 的多相机检测性能，且在相机重叠区域优势尤为显著。

核心论点：用稀疏的 3D object query + 反向投影替代 dense depth 估计与后处理，把多相机 3D 检测从”逐图预测 + 跨图合并”重塑为”以物体为中心的 set prediction”。

2. 问题与动机

多相机 3D 检测在 DETR3D 之前主要有两条路：

方案 代表 核心问题
2D 检测器 + 3D 预测头 FCOS3D / CenterNet 每个相机独立推理，需要逐图 NMS + 跨图全局 NMS 合并；忽略了相机几何
Pseudo-LiDAR PackNet + CenterPoint 依赖 dense depth 估计，深度误差与检测误差级联放大

两类方案的共同弱点：

  • 跨相机融合靠后处理，重叠区域（约占 nuScenes val 中 9.7% 的 GT box）的目标容易被切断或重复；
  • 显式 depth 预测在分布外场景容易过拟合，是误差的主要来源；
  • NMS 不可并行，是推理瓶颈。

核心痛点：如何在不依赖 dense depth、不依赖 NMS 的前提下，让多相机几何信息从一开始就参与到检测计算中？

3. 核心洞察

洞察 1：用 3D-to-2D 反向投影替代 depth 估计

传统 pseudo-LiDAR 路线是 2D image → depth → 3D point → 3D detector，每个像素都要估一次深度，误差沿链路累积。本文反过来：从 3D 空间中一组可学习的 object query 出发，每个 query 解码出一个 3D 参考点 ，再用相机变换矩阵把它反投影到每个相机的图像平面：

只在反投影点处做双线性插值取特征，不需要在整张图上估 depth。这样把”先估深度后回归”改为”先假设 3D 位置后取证据”，从根本上避免了 depth 预测模块的复合误差。

洞察 2：单点投影到全部相机，自动完成多视角融合

同一个 3D 参考点天然会落到所有可见的相机视图里。本文对每个 query 收集所有相机 × 所有 FPN 层级的特征，按可见性掩码 （投影是否落在图像平面内）做归一化平均：

不再需要”先各相机出框，再跨相机合并”这种后处理逻辑。论文在 nuScenes 重叠区域的对比中，DETR3D 的 NDS 比 FCOS3D 高出约 5–6 个点，验证了”在每一层就跨视角融合”的优势。

洞察 3：Set-to-set loss + 迭代精修，去掉 NMS

延续 DETR / Deformable DETR 的思想，用 Hungarian 匹配 + focal + L1 loss 做集合预测：

并把 detection head 堆叠成 6 层，每一层都做 “解码参考点 → 投影 → 采样 → self-attention → 输出 box”，逐层精修。消融显示从 layer 0 到 layer 5，NDS 从 0.380 单调上升到 0.425，验证了迭代精修的必要性。整套推理过程完全不需要 NMS。

三个洞察的递进关系

  1. 表示：用 3D query 替代 dense depth；
  2. 几何：用反投影替代后处理融合；
  3. 监督：用 set loss + 迭代 refine 替代 NMS。

三个关键数字：

  • 0.425 / 0.346：nuScenes val 上 ResNet101+DCN backbone 的 NDS / mAP；
  • 6 层 decoder：每层都做”投影—采样—attention—预测”的迭代 refine（layer 0 → 5：NDS 0.380 → 0.425）；
  • 900 个 object queries：消融显示 query 数量增加到 900 后性能饱和（mAP 0.346）。

关键发现：

  1. 不用 NMS、不用 dense depth，依然达到与 SOTA 持平甚至更优的精度；
  2. 速度误差（mAVE）显著低于 FCOS3D（0.842 vs 1.292），说明 query 直接回归 3D 速度比 2D-to-3D 解码更稳定；
  3. 在相机重叠区域（约 9.7% 的 GT box），DETR3D NDS 0.384 vs FCOS3D 0.329，优势明显。

5.3 性能瓶颈分析

  • mATE 偏高（DETR3D 0.773 vs FCOS3D 0.725）：避免 depth 估计的代价是位置精度略弱，因为 FCOS3D 直接显式监督 box depth；
  • 单点采样的感受野有限：每个 query 在每个相机里只取 1 个像素位置，论文 Conclusion 自己指出这是后续可以扩展的方向（→ 后续 PETR / Sparse4D 的 deformable / multi-point 采样）；
  • 训练效率：12 epoch / 8× RTX 3090 / 约 18 小时，batch size = 1/GPU，吞吐受限于多视角输入。

5.4 失效场景分析

论文 Figure 3 展示了若干典型情况：

  • 远距离正前方车辆漏检（CAM_FRONT 中较远的小目标未被检出）——单点采样 + 远处 GT 在图像中尺度极小所致；
  • 未标注但被检出的物体（CAM_BACK_LEFT 中模型检出了未在 GT 标注的车）——侧面反映模型 recall 较好，但也可能在评估时被算作 FP；
  • 相机重叠区域虽显著优于 baseline，但绝对 NDS 仍只有 0.384，说明跨视角对齐并没有完全解决。

6.2 复现要点

  1. 3D 参考点的归一化坐标范围必须与 pc_range（点云感知范围）一致，否则反投影点会落到图像之外，导致 mask 全 0、梯度消失；
  2. 相机变换矩阵 lidar2img 必须包含整套 intrinsics + extrinsics + 数据增强（如 resize/crop/flip）的复合变换，少考虑任意一个增强都会让监督信号失真；
  3. 可见性 mask 要同时检查 z > 0 和归一化坐标在 [-1, 1] 内，缺一会引入虚假梯度；
  4. 每层都要计算 loss（深监督），否则前几层 query 不会被有效学习，迭代 refine 会退化；
  5. FCOS3D backbone 初始化：论文实现里 ResNet101+DCN 是从 FCOS3D 预训练权重初始化的，从 ImageNet 直接训会显著掉点；
  6. batch size = 1 / GPU 是显存现实，多视角输入注意 BN 改为 SyncBN。

6.3 性能优化方向

精度提升

  • 单点采样 → 每个 query 取多个采样点（沿后续 Deformable DETR / Sparse4D 思路），增加感受野；
  • 引入时序：当前帧 query 由上一帧 propagate 而来（StreamPETR / Sparse4D 已沿这条路演进）；
  • 加入 LiDAR / Radar 模态，弥补 mATE 偏高的弱点。

速度优化

  • 减少 decoder 层数（6 → 3）通常会折损一定 NDS，但推理延迟可显著下降，是实际部署常用折中；
  • 把 grid_sample 与可见性 mask 融合到自定义 CUDA kernel，减少 kernel launch 开销；
  • query 投影矩阵预计算（推理期相机参数固定时），把 runtime 矩阵乘法换成查表。

7. 研究启示

7.1 可迁移的思想

  • “先假设 3D，再回 2D 取证据”：把 ill-posed 的 2D-to-3D 问题反过来做，是后续 BEVFormer、PETR、Sparse4D 共同的范式起点；
  • “以物体为中心的稀疏表示”：稀疏 query + set prediction 让网络绕过 dense BEV 编码，对 scaling 友好；
  • “几何由相机参数决定，特征由网络学习”：把可解释的几何变换与可学习的语义特征解耦，工程上更稳健；
  • “逐层迭代 refine 替代 single-shot”：每层都做”投影 + 采样 + 预测”的循环，是 transformer 头部设计的通用模板。

7.2 方法局限

  1. 单点采样导致每个 query 的感受野很小，对小目标和遮挡目标不友好；
  2. 没有显式时序建模，速度回归靠隐式监督，长程跟踪能力弱；
  3. mATE 仍偏高，跨车型部署时对外参标定误差较敏感（projection-based 路线的共同问题）。

7.3 技术影响

  • 是 PETR、Sparse4D、StreamPETR 等”sparse query”路线的直接前身——后者基本都在 DETR3D 的 query 表示上加 embedding-based 几何、多点采样、时序传播等模块；
  • 推动了多相机 3D 检测从”逐图 + 后处理”向”端到端 + set prediction”的范式迁移；
  • 在工业界，DETR3D 的”3D query 反投影 + bilinear 采样”模板被广泛用作快速原型搭建的起点，验证某个稀疏感知想法是否值得继续投入时常以它为 baseline。
