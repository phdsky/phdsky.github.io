TransTrack：用双查询兼顾新目标发现与轨迹传播

2020-12-31

Original title: TransTrack: Multiple Object Tracking with Transformer
Task: Online Multi-Object Tracking
Method: object query / track query, Transformer, IoU association
Venue: arXiv 2020
Year: 2020
Authors: Peize Sun, Jinkun Cao, Yi Jiang, Rufeng Zhang, Enze Xie, Zehuan Yuan, Changhu Wang, Ping Luo
Paper: 原文
Code: 作者仓库
Version: arXiv v2（2021-05-04）；date 保留 v1 首次公开日；核验于 2026-10-24。实验数值均为作者报告，未作本地训练复现。

一句话总结

TransTrack 用可学习的 object queries 发现当前帧目标，用上一帧实例特征形成的 track queries 传播已有身份，再在当前帧中匹配两路预测框。它把跨帧关联的一部分移入网络，但推理仍有 IoU + Hungarian 匹配，不能等同于完全无匹配的跟踪器。原文 §3

研究背景与动机

检测负责“现在有哪些物体”，跟踪负责“哪些是以前的物体”。如果只沿用单目标跟踪的 query-key 思路，将历史目标特征作为查询，系统就没有查询能代表刚进入画面的新目标；反过来，独立检测查询虽然能找到新目标，却不会自然获得跨帧稳定身份。

本文的关键拆分是：新生发现与身份延续使用不同来源的查询，读同一份图像证据。 这种拆分比笼统地说“给 MOT 加 Transformer”更准确，也解释了为什么两路查询缺一不可。

方法详解

信息流与状态

两路 decoder 结构相同，查询来源不同；不能据此默认权重完全共享。上一帧特征被缓存以减少重复 backbone 计算。检测分支覆盖所有当前目标，传播分支寻找旧目标在当前帧的位置，最后匹配发生在同一时刻的两套框之间，而非简单比较前后两帧原始框。

训练与关联

这里的训练期预测—真值匹配与推理期 detection—tracking 框匹配是两件事。track query 的身份连续性来自历史实例特征；检测查询编号本身不是永久 ID。

推理时，匹配上的检测继承旧轨迹身份，未匹配的检测创建新轨迹。未匹配旧轨迹可以暂时保持 inactive，论文使用 帧的 track rebirth 窗口。该机制支持短时消失后的恢复，但不构成长时跨镜头重识别系统。§3.1–3.3

哪个实验支持核心论点

Table 3 在 MOT17 划分验证集上的查询消融更能解释方法：仅 object query 为 58.3 MOTA，两路查询为 65.0；仅 track query 的 FN 比例达到 93.8%，因为新目标持续漏检。双查询将“能检测”与“能延续身份”合到同一框架，但测试集上 74.5 MOTA 与 63.9 IDF1 的差距也提示：召回改善不等于身份已经稳定。Table 1、3

亮点、局限与启发

  • 亮点： 将历史实例特征直接作为查询，避免为每条轨迹重新裁剪图像并独立运行外观网络；新生查询则解决递归传播的覆盖盲区。
  • 局限： 两套框仍要融合，错误传播与有限的失活窗口仍会影响遮挡恢复。论文以 MOT17/20 行人跟踪为主，不能直接推出跨类别或强非线性运动的泛化能力。
  • 工程判断： 复现应分别检查检测召回、传播框质量和融合匹配。只调最终 IoU 阈值，无法修复上游查询没有捕获目标的问题。
  • 研究启发： “历史实例是状态”成为后续 query 跟踪的重要思路；但后来的递归 query 跟踪、MOTIP 的上下文 ID 分类和本方法的两路框匹配，训练目标与推理接口并不相同。

相关工作

CenterTrack 用历史 heatmap 与位移预测表达时间信息；TransTrack 将其转到实例特征查询。MOTIP 则将历史轨迹作为带 ID 标签的上下文，直接学习身份分配。两者都使用 Transformer，但不能只按网络名称归为同一种关联算法。
