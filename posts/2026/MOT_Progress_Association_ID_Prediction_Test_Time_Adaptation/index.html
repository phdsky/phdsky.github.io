MOT 算法进展：从候选框关联到身份预测与测试时适应

2026年10月24日

Topic: Online 2D Multi-Object Tracking
Scope: 2020–2026；重点讨论检测框级在线 MOT，资料核验截至 2026-10-24。
Evidence: 八篇指定论文全文精读，并补充 MOTR、BoT-SORT、OC-SORT、MeMOTR、HyperSSM 与 MOTIP2 的一手来源。所有结果为作者报告，未作统一重训练或本地基准复现。

核心问题：怎样让一个身份穿过不完整的观测

多目标跟踪需要同时输出目标位置与持续身份。难点不只是“框是否准确”，还包括一个人被遮住后能否继续沿用原 ID、两个外观相似的人交叉时能否避免身份交换，以及新出现的框究竟代表新目标还是旧轨迹的重复检测。

从这组论文看，近年的进展并不是一条“传统方法被 Transformer，再被扩散模型替代”的单线。更有解释力的主线是：系统保留什么证据、用什么状态记住历史、让谁来决定身份，以及测试时如何纠错。 检测与身份表征、候选利用、运动预测、可学习关联、测试时适应仍在并行发展。

图为本文按方法接口重新整理的示意，不表示引用谱系，也不表示后一个方法完全替代前一个。日期采用会议/期刊年份或 TransTrack 的首次预印本年份；各精读另列首次公开日期。

1. 先把任务、指标和比较协议说清楚

1.1 一条实用的信息链

框架之间的差别在于哪些环节是显式模块，哪些被网络联合学习。端到端训练描述优化关系；online 描述推理能否只读已经到达的数据；real-time 描述在某硬件和输入下是否满足目标时延。三者相互独立。一个关联器不使用 Hungarian，也仍可能需要阈值、身份冲突处理和轨迹出生/终止逻辑。

2. 2020–2021：检测与身份表征开始共同设计

FairMOT：共享网络需要处理任务冲突

FairMOT 精读 从中心采样、多尺度特征、低维 embedding 和损失平衡入手，使检测与 ReID 在同一网络里共同工作。它的重要性在于提醒我们：共享 backbone 只说明共享计算，并不自动保证共享特征适合两个目标。

例如，检测希望同类别实例在语义上接近，ReID 却要区分这些实例；高维身份分支也可能反过来损伤检测。FairMOT 的结果支持有意识地设计接口与监督，而非仅在现成检测器后加一个分类头。

QDTrack：增加有用的身份监督覆盖

QDTrack 精读 将同一对象的多个 proposals 纳入多正样本对比学习，让关联特征接触真实检测误差。推理的 bi-softmax 与 backdrops 又处理了双向一致性、无匹配对象和背景干扰。

两篇工作分别改善“在哪里读取身份特征”和“哪些区域对参与训练”。它们不是互斥答案。QDTrack 在指定 BDD100K 设置中表明 appearance-only 可以很强，也不等于运动线索已经失去价值。

TransTrack：历史实例成为查询

TransTrack 精读 用两类查询分别承担新目标发现与旧目标传播。相比 CenterTrack 的历史 heatmap/位移接口，它把历史状态移到实例特征空间。

但 TransTrack 仍输出两套框，并用 IoU + Hungarian 融合。把它直接写成“Transformer 消除了匹配”会掩盖关键机制。其价值在于让历史状态参与感知，而不只是拿两帧独立检测结果做后处理。

3. 2022–2025：显式关联持续进步，候选和轨迹管理不可忽略

ByteTrack：低分不是无用

ByteTrack 精读 让低分检测在高分关联之后参与旧轨迹恢复。它利用了单帧检测分数没有表达的时间证据：一个框虽然看不清，但若与已存在目标的运动位置一致，仍可能是可靠延续。

这与简单降低检测阈值不同，因为低分框不直接创建新轨迹。BYTE 的可插拔性也表明，很多性能瓶颈来自信息被上游过早删除，而不只来自模型容量。

BoT-SORT 与 OC-SORT：重新审视运动和观测

BoT-SORT 将运动、外观、摄像机运动补偿和状态表示改进组合起来；OC-SORT 针对遮挡期间运动估计误差累积，使用检测观测构造虚拟轨迹以重新更新状态。二者说明：线性滤波器的误差往往还来自状态更新和观测使用方式，不能仅凭“运动非线性”就断言必须换成复杂网络。

这里仅概述其与主线的联系，不将其历史榜单成绩当作当前排行。

TrackTrack：让更多候选竞争，但约束新生

TrackTrack 精读 将 BYTE 的低分恢复扩展到 NMS 删除的高分候选，并在联合候选池上执行双向最小代价的迭代分配。TAI 则利用已匹配轨迹压制重复新生。

它揭示一个系统性关系：保留更多候选可以提高恢复机会，但也会增加重复框与假轨迹风险，所以关联策略与新生规则需要配套。论文的完整系统还包含外观、相机补偿和后处理，最终成绩不是单独换一个匹配算法的全部收益。

4. 2024：非线性运动从手工模型走向数据驱动预测

DiffMOT 精读 把下一帧四维框位移作为生成目标，以过去框和位移为条件，用解耦扩散实现单步预测。它保留检测与显式关联，因此贡献可以较清楚地定位到运动预测接口。

与仅拿 Kalman 比较相比，论文中 Transformer 运动预测器到 D²MP 的消融更能检验扩散设计的附加价值。完整系统对照还需固定外观权重和候选策略。SportsMOT 的 76.2 HOTA 使用 train+val 训练检测器，train-only 对应 72.1；忽略星号协议会制造虚假的跨论文优势。

从算法选择看，运动模型应首先服务于关联：预测均方误差降低不一定改善身份保持，尤其当两个目标彼此接近时。相反，一个不完全物理准确、但能把正确候选留在可匹配范围内的预测，也可能更有用。这是本文的工程分析，不是 DiffMOT 单篇实验已经证明的普遍定理。

5. 2022–2025：从传播 query 到直接预测身份

MOTR 以跨帧递归更新的 track query 表示实例，通过轨迹感知标签分配训练；MeMOTR 引入长期记忆以稳定轨迹嵌入。它们让“历史如何进入模型”从前后帧配对扩展到更长的状态维护。

MOTIP 精读 则改变目标表述：ID 无需固定语义，只需在历史上下文中保持一致。给历史轨迹贴上可复用 token，当前检测根据上下文分类为其中一个 ID 或 newborn，就能直接监督身份决策。

表述 学习的主要对象 推理中身份如何得到
FairMOT / QDTrack 身份可区分的 embedding 外观/运动代价与关联策略
TransTrack 新目标检测与旧目标框传播 两路框匹配后继承 ID
MOTR / MeMOTR 跨帧实例状态与 query 更新 递归轨迹状态延续
MOTIP 当前对象相对于历史标签的 ID 分布 ID 分类、冲突处理与新生规则

MOTIP 的意义不是“终于不需要任何规则”，而是把最核心的身份判定变为可学习任务。字典容量、回收、阈值、历史污染仍然存在。训练中随机遮挡与 ID 交换正是为模拟这种不完美历史。

6. 2026：适应、群体运动关系与空间先验

TCEI：对已学会的 ID 预测做测试时校准

TCEI 精读 在 MOTIP 上引入短期直觉记忆和历史经验缓存，分别利用可信与不确定样本。它把关注点从“如何在训练数据上学关联”移向“测试时面对新分布如何调整已有判断”。

同一论文内，无适应到 TCEI 的 DanceTrack HOTA 为 69.5→70.6，AssA 为 60.2→62.3，FPS 为 14→12。收益主要体现为关联改善，代价是额外状态与计算。跨视频缓存使测试顺序、重置策略和 ID 对齐成为实验协议的一部分，不能再只记录一个模型 checkpoint。

原文存在 AssA 63.3/62.3 的正文—表格差异，本系列统一使用表格的 62.3；公式与公开代码的差异也已列在精读中。

HyperSSM：运动估计从单条轨迹走向对象间协同

CVPR 2026 的 Hypergraph-State Collaborative Reasoning for Multi-Object Tracking 用动态超图描述相关对象的运动关系，并结合状态空间模型处理时间连续性。与 DiffMOT 主要从单个对象历史条件预测相比，这一方向强调多个相关目标之间的互相约束。这里依据正式论文入口与方法描述归纳方向，不将其成绩纳入未经统一协议审计的排行。

MOTIP2：可学习关联也可以显式接收空间先验

2026-10-07 公开的 MOTIP2: Spatial Priors for End-to-End Multi-Object Tracking 在数据增强、损失与表示三个环节加入空间先验：让 ID 交换更接近空间混淆、按框距离调整身份错误代价，并给轨迹 token 显式位置。其模型基于 DEIM 检测 Transformer，因此不能把与原始 MOTIP 的所有差距都归因于某一个先验。这一条按当前 arXiv 版本介绍，未进行与八篇精读相同深度的全文/代码审计。

这三种方向共同说明，学习式跟踪与显式先验仍会结合；当前进展关注的是把什么约束放到哪个环节，而不是一味增加网络规模。

8. 对阅读和工程选择的启发

如果问题是遮挡造成分数下降，先检查候选是否被阈值或 NMS 过早删除；如果框都在但交叉时换 ID，重点查看表征、关联代价和历史状态；如果预测框偏离导致正确匹配没有机会，才需要针对运动模型诊断。新场景中持续退化，则进一步检查训练分布、置信度及缓存污染。

已观察到的失败 值得优先研究的机制 必须同时核对
遮挡时低分目标断轨 BYTE、TrackTrack 候选利用 假阳性和重复新生是否增加
类内外观难区分 QDTrack、FairMOT 表征学习 检测性能是否被牺牲
急转、快速运动、预测漂移 OC-SORT、DiffMOT、协同运动建模 摄像机运动与坐标尺度
长历史身份决策不稳定 记忆式 query、MOTIP 历史错误、窗口、ID 容量
域变化下关联退化 TCEI 类测试时校准 顺序、重置、无标签约束和延迟

这是一张基于论文机制的诊断地图，不是未经测试的部署性能承诺。可靠选型最终要回到目标视频、固定检测器、相同延迟预算和可复查的错误案例。特别是端侧系统，检测、ReID、缓存与关联的开销都要计入，而不是选取论文里最漂亮的单模块 FPS。
