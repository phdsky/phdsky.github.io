多目标跟踪的身份之问：从位置匹配到时序记忆

2026-10-24

Topic: Multi-Object Tracking
Keywords: 身份关联、运动预测、外观特征、轨迹记忆、端到端跟踪

引言：框住一个人，为什么还会跟丢？

想象一段路口监控：两个人迎面走来，在画面中央交叉，其中一人被公交车挡住，几秒后从另一侧出现。对人来说，我们会结合衣服、走路方向和先前的位置，判断“这还是刚才那个人”。对机器来说，这个判断并不包含在一个检测框里。

目标检测回答的是：这一帧里有什么，在哪里？ 多目标跟踪（Multiple Object Tracking，MOT）还要回答：这一帧里的对象，与之前的哪个对象是同一个？

看起来只是给检测框多加一个编号，背后却需要处理消失、重现、交叉、误检和记忆。一个检测器可以在每一帧都把人框得很准，跟踪器却在两人交叉后把编号交换。视频里的人没有变，机器理解的身份已经变了。

理解 MOT，可以顺着一条问题链往下走：先用位置把框连起来；位置不够，就学习外观；遮挡让框变得不可信，就重新考虑哪些检测值得保留；短期线索仍不够，再让网络维护历史、直接判断身份。这里每一步都在扩大系统能利用的证据，也都引入了新的取舍。

图中的编号代表视频内的轨迹身份。遮挡期间没有可靠检测时，系统可以暂存轨迹；重新看见目标后，还需要判断是否恢复原编号。

1. 跟踪到底在跟什么？

1.1 检测框是观察，轨迹是记忆

检测器每次读取一张图像，输出一组边界框、类别和置信度。边界框通常用四个数描述位置和尺寸；置信度表示检测器对当前预测的确信程度。它们都属于当前帧的观察。

轨迹（track）则是跨帧保留的一份对象记录。 它可以保存编号、最近位置、估计速度、外观特征，以及已经多久没有匹配到新检测。因此，“这一帧没有检测到”与“这个对象已经离开”是两回事。

最常见的跟踪器会反复执行这样的循环：

把当前检测归给某条已有轨迹，叫作数据关联（data association）。无法归给旧轨迹的检测可能是新对象，也可能是假阳性；暂时没有检测对应的旧轨迹可能被挡住，也可能已经离开。一个完整的跟踪器必须同时处理这些情况。

1.2 ID 是临时编号，不是真实身份

视频里的 ID 7 不需要表示某个真实姓名。只要同一目标一直用 7、另一个目标一直用 12，跟踪就可以是正确的。把整段视频中的 7 与 12 整体互换，也不会改变对应关系；但只在交叉之后交换，就产生了身份切换（ID switch）。

本文关注单摄像头视频中的二维框跟踪。跨摄像头寻找同一个人、预测三维运动、为每个像素分配对象身份，分别还涉及其他任务设定。先把“当前框属于哪条历史轨迹”理解清楚，就掌握了进入 MOT 的共同入口。

还有一个常见误会：online 指只能使用当前和过去的帧，并不表示必须联网，也不保证运行得快。 离线方法可以回看未来帧修正结果；实时方法还要满足具体设备上的处理时限。端到端则主要描述训练和模型组织方式，不能与这两个词互换。

2. 第一条路线：先检测，再把框连起来

2.1 SORT：用一个简单假设启动跟踪

如果一个人上一帧向右走，这一帧大概率还在附近继续向右走。2016 年的 SORT 将这个直觉落实为一套简洁组合：用 Kalman 滤波器估计运动，再用 Hungarian 算法完成检测与轨迹的分配。

Kalman 滤波器可以先理解为一个不断修正的预测器：根据历史状态预测下一刻的位置，获得新检测后，再结合预测的不确定性修正估计。SORT 使用近似恒定速度的运动模型，能处理常见的短时平滑运动。

随后，系统比较预测框与检测框的重叠程度。常见的 IoU（交并比） 就是“两个框重叠的面积，除以它们覆盖的总面积”：完全重合时为 1，完全分离时为 0。重叠越多，通常越值得考虑为同一个对象。

2.2 为什么不能让每个人都选最近的框？

因为两个旧轨迹可能同时看中一个检测。下面是一组用于解释分配问题的假设代价，数值越小表示越合适：

关联代价 当前检测 A 当前检测 B
旧轨迹 1 1 2
旧轨迹 2 2 100

若轨迹 1 抢先选择 A，轨迹 2 就只剩下代价 100 的 B，总代价为 101。若让轨迹 1 选 B、轨迹 2 选 A，总代价只有 4。Hungarian 算法解决的就是这类一对一整体分配问题；实际系统还会通过阈值拒绝不合理的匹配，允许目标暂时不配对。

但“总成本最小”只是在给定代价矩阵下最优。如果代价本身把两个人看反了，再精确的分配算法也无法凭空找回真实身份。 这正是后续方法不断改变运动、外观和历史表示的原因。

2.3 简单位置匹配的边界

两个人交叉时，位置可能接近；遮挡持续一段时间后，预测误差会累积；镜头突然平移时，所有框都可能一起移动。只凭相邻位置判断身份，证据很快就不够用了。

SORT 建立了一个重要起点：检测与关联可以拆开，先用清晰的状态和匹配规则搭起系统。下一步的问题是，除了“在哪里”，能不能再记住“长什么样”？

3. 从位置到外观：机器需要怎样的“相貌记忆”？

3.1 DeepSORT：给轨迹补上一份外观描述

2017 年的 DeepSORT 在 SORT 基础上加入深度网络学习的外观信息。网络把一个人的图像区域转换成一串数字，称为特征向量（embedding）。目标是让同一人的不同观察更接近，不同人的观察更容易区分。

这里的重识别（Re-Identification，ReID）不一定需要看到脸。衣服颜色、纹理和身体轮廓都可能提供线索。一个人被遮住后重新出现，即使位置预测已经不准，历史外观仍可能帮助恢复对应。

外观也有自己的弱点：队服相同的运动员、穿着相近的舞者，可能很难区分；光照、视角和遮挡又会让同一个人的特征发生变化。于是运动与外观往往需要互补，任何一项都不宜被当成永远可靠的身份证。

3.2 FairMOT：找人和认人，能否共享一个网络？

给每个检测框再跑一次外观网络，会增加计算。FairMOT 关注的是联合检测与身份特征学习：共享图像特征，同时输出位置和外观描述。

这带来一个容易被忽略的冲突。检测需要知道“这些都是人”，身份区分却需要知道“这些人彼此不同”。共享网络并不会自动让两项任务配合良好。FairMOT 从目标中心采样身份特征，结合特征维度和训练损失的平衡，减少两项任务之间的干扰。

可以把它理解为：一份视觉表示既要支持分类，又要保留实例差异。计算共享是收益，如何让两项任务都得到合适的特征，才是方法设计的重点。

3.3 QDTrack：训练时也应该见过“不完美的框”

同一个人可能对应多个候选框：有的框得紧，有的略微偏移，有的只覆盖部分身体。如果训练只关注少数理想框，实际检测的抖动就可能让身份特征变得不稳定。

QDTrack 用更多候选区域构造训练对：同一目标的区域作为正样本，不同目标的区域作为负样本，学习哪些观察应当靠近、哪些应当分开。它改变的是身份监督的覆盖范围，而不只是换一个更大的外观网络。

走到这里，MOT 已经有了位置和外观两种证据。但还有一个更靠前的问题：如果正确的检测框在进入关联之前就被删掉，后面的特征再好又有什么用？

4. ByteTrack 的转折：低分框也可能是关键证据

4.1 遮挡为什么容易导致断轨？

假设一个人无遮挡时的检测分数是 0.92，被公交车挡住一半后降到 0.35，而系统只保留高于 0.5 的框。此时，人仍在画面里，检测器也给出了候选，只是候选被阈值过滤掉了。跟踪器看到的却是“这个人消失了”。

这些分数只是说明机制的例子。关键在于：单帧检测分数与跨帧身份可信度并不等价。 一个低分框若恰好出现在旧轨迹预计的位置，仍然可能是有用证据。

4.2 两次关联，承担不同责任

ByteTrack 的 BYTE 关联策略先用高分检测匹配轨迹，再让剩余轨迹尝试匹配低分检测。低分框因此获得了恢复旧目标的机会。

这套设计没有把所有低分框都变成新对象。低分框可能是遮挡目标，也可能是背景；允许它延续一条有历史证据的轨迹，与允许它独立创建新轨迹，是两种不同的决策。

ByteTrack 的启发很直接：除了改善预测，还可以重新检查系统有没有过早丢弃信息。跟踪拥有时间上下文，应当有机会重新判断检测器不太确定的观察。

4.3 TrackTrack：去重时删掉的框，也值得重新审视

检测器常用非极大值抑制（NMS）去掉高度重叠的重复框。它有助于避免一个人被检测多次，但在人群拥挤时，也可能压掉对某条轨迹有用的候选。

TrackTrack 进一步利用这类候选，从轨迹角度组织匹配，并让已有轨迹参与新轨迹的去重。这里形成了一对必须共同处理的问题：保留更多框可以减少漏关联，却也可能制造重复身份。候选利用和轨迹出生规则需要一起设计。

这条路线仍在使用显式关联，但它优化的已经不只是“怎么求解代价矩阵”，还包括“让哪些证据进入矩阵，以及什么时候相信一个新身份”。

5. 运动并没有过时：从预测位置到理解变化

5.1 错的是运动模型，还是使用观测的方式？

回到路口：如果相机正在转动，即使行人站着不动，他在图像中的框也会移动。因此，图像坐标变化混合了目标运动和摄像机运动。

BoT-SORT 将运动、外观和摄像机运动补偿结合起来。补偿的直觉是先估计画面整体如何变化，再判断对象相对场景怎样移动。OC-SORT 则关注遮挡期间的预测漂移：目标重新被观测到后，利用观测信息修正中间的运动估计。

它们提示我们，同一个滤波框架可以因状态表示、观测更新和相机处理方式不同而表现不同。看到运动预测失败，应该先定位误差来自哪里。

5.2 DiffMOT：从历史中学习非线性位移

舞者突然转身、运动员急停变向，很难一直符合近似匀速假设。DiffMOT 根据历史检测框与位移，学习下一帧框如何变化。

它使用扩散模型，但生成的不是图片，而是描述框运动的少量数值。扩散可以先理解为一种“训练时学习从受扰动的数据恢复目标”的建模方式；DiffMOT 用解耦设计实现单步运动预测，避免依赖很长的迭代采样过程。

这并没有把整套跟踪都换成生成模型。预测器给出目标可能到达的位置，之后仍要与当前检测关联。扩散改进的是运动接口，身份是否保持正确，仍取决于候选、外观、匹配和轨迹管理。

对初学者而言，一个很有用的阅读习惯是：看到 Transformer、扩散或状态空间模型，先问它究竟替换了流程中的哪一块。模型名字相似，不代表它们解决的是同一个问题。

6. 第二条路线：让网络带着历史看当前帧

6.1 从“检测完再匹配”到“带着记忆找目标”

前面的经典流程先完成当前帧检测，再使用历史做关联。另一种思路是更早引入历史：既然上一帧已经知道一个人在什么位置、具有怎样的特征，当前检测时就可以用上这些线索。

CenterTrack 将历史目标位置表示为热力图，与图像一起输入网络，并预测帧间位移。热力图可以理解为一张在目标位置点亮的地图：它把“刚才在哪里看到过人”交给当前感知过程。

到了 Transformer 路线，历史不必只表示成空间上的亮点，还可以表示成一串随时间更新的特征。

6.2 Query 是什么？一份会更新的对象记录

Transformer 中的 query 可以先理解为一组向图像特征读取信息的向量。用于跟踪时，它可以携带某个对象过去的信息，在当前帧寻找与其相关的视觉证据。它不是人写的一句自然语言问题，也不是天然正确的身份标签。

TransTrack 分别使用可学习的对象查询发现目标、使用历史实例特征传播已有目标。两路结果仍通过 IoU 与 Hungarian 匹配融合，因此使用 Transformer 并不意味着已经取消显式分配。

MOTR 则通过逐帧传递和更新 track query 表示被跟踪实例，让训练直接约束轨迹身份的延续。MeMOTR 进一步利用长期记忆稳定实例表示。

这些方法把更多关联责任交给网络，同时也让“历史记错了怎么办”成为核心问题。一次错误更新可能污染后续状态，记忆更长并不自动意味着记忆更可靠。

7. 路线之争：规则与学习，究竟在争什么？

将这些方法放到一起，真正的分歧是：身份决策中的哪些部分应该显式设计，哪些部分应该从数据中学习？

观察角度 显式关联为主 学习身份与时序状态为主
怎么使用历史 位置、速度、外观等可解释状态 实例 query、上下文 token、学习到的记忆
怎么决定对应 构造代价，再匹配和筛选 学习状态延续或直接预测 ID
诊断错误的入口 检测、运动、相似度、阈值 历史表征、注意力、身份监督、状态更新
常见挑战 规则之间的配合、场景变化 训练数据、历史污染、计算与状态管理

这张表描述主要分工，实际方法经常跨越两边。显式关联可以使用很强的深度特征，端到端模型也可以接收手工设计的空间约束。端到端训练让相关部分有机会共同优化，但不会消除遮挡、歧义和错误历史。

7.1 空间先验重新进入学习式跟踪

2026 年 10 月公开的 MOTIP2 在数据增强、损失和轨迹表示中加入空间先验。例如，训练时更关注空间上容易混淆的身份交换，让模型显式获得目标位置。

其出发点很直观：一个人通常不会在极短时间内跳到画面另一端。网络可以尝试自己学会这个限制，也可以由设计者提供有用的约束。MOTIP2 基于 MOTIP 改造，同时采用 DEIM 检测器；理解思想时可以关注先验，比较成绩时则必须同时考虑检测器变化。

7.2 运动线索也可以来自周围对象

HyperSSM 将对象间的关联运动与时间状态建模结合起来。对初学者而言，“超图”可以先理解为一种连接多个相关对象的结构：不只观察一个目标自己的过去，还尝试利用一组对象之间的运动关系。

这种方向扩大了历史证据的范围，也增加了区分目标自身运动、群体运动和摄像机变化的难度。它与单轨迹运动预测并不是简单的前后替代关系。

7.3 TCEI：测试时，能不能利用刚积累的经验？

模型训练结束后，新的摄像机、光照和运动分布仍可能使身份判断失准。TCEI 在 MOTIP 上引入近期记忆和经验缓存，用测试过程中已经获得的特征与预测校准当前 ID 分数，不依赖在线反向传播。

这可以理解为让系统参考近期观察来调整判断，但缓存没有人工提供的正确答案：它保存的也可能是错误预测。如何避免错误不断强化、何时重置状态，以及额外计算是否值得，都成为方法的一部分。

从显式规则到学习式记忆，再到空间先验和测试时校准，MOT 的发展正在围绕证据如何进入系统展开。位置、外观与历史没有失去价值，它们被放进了新的表示和决策方式里。

8. 怎样看懂一张跟踪成绩表？

8.1 框得准和认得准，要分别看

设想两段输出：第一段始终有框，但每次交叉都会换 ID；第二段偶尔漏一帧，却能持续跟住同一人。只数框的数量，无法判断哪一个更符合应用需要。

常见指标大致回答不同问题：

指标 入门时先理解的问题
MOTA 漏检、误检、身份切换合起来造成多少错误？
IDF1 从整段轨迹的身份对应看，识别得是否完整且一致？
HOTA 检测质量与关联质量是否同时做好？
DetA / AssA HOTA 所衡量的检测与关联两方面，短板分别在哪里？

MOTA 中漏检、误检往往比身份切换数量多，因此更强检测器可能显著提高 MOTA，却没有同等幅度改善身份保持。HOTA 则在不同定位阈值下共同评估检测与关联；它适合帮助识别“框很好，身份却很乱”的情况。

数据集也在改变我们看见的问题。MOT17/20 常用于行人和拥挤场景；DanceTrack 强调相似外观与复杂运动；SportsMOT 将运动场景带入测试。一个方法在不同数据集上的相对优势可能变化，这往往能反映它依赖的线索。

8.2 分数增加了，究竟是哪一部分起了作用？

以 TCEI 自身的 DanceTrack 对照为例，MOTIP 基线到 TCEI 的 HOTA 从 69.5 升至 70.6，AssA 从 60.2 升至 62.3，DetA 从 80.4 变为 80.2；作者报告的速度从 14 FPS 变为 12 FPS。结合起来看，主要收益体现在关联，同时付出了额外运行开销。结果与设置

这是同一研究内的对照，仍要按其数据和实现条件理解。跨论文比较时，还需要核对检测器、训练数据、测试划分和后处理。例如，完整视频处理结束后再补齐缺失框的插值操作，不能当成当前帧立刻获得的结果。

速度同样要问清楚：是否包含检测、外观网络、关联与后处理？只计预先算好检测之后的关联速度，和从原始视频开始计时，会得到完全不同的 FPS。读表的目标是理解收益来自哪里，而不只是找到最大数字。

9. 回到最初的路口：一条身份怎样穿过遮挡？

现在再看开头的场景。人还没被挡住时，系统积累了位置和外观；遮挡出现后，低分检测可能仍提供延续线索；短暂消失期间，运动状态或轨迹记忆保留了一个待确认的身份；重新出现时，系统综合当前观察与历史判断是否恢复原编号。新对象进入时，还要避免把它强行接到一条旧轨迹上。

每个算法都在这条链上的不同位置作出选择。ByteTrack 让不确定的检测有机会被历史支持，FairMOT 和 QDTrack 改善可比较的实例表征，DiffMOT 改变运动预测，MOTR 和 MOTIP 把更多身份决策交给时序学习，TCEI 再尝试利用测试时经验调整判断。

开始实践时，可以先找一段包含交叉和遮挡的视频，观察编号在哪一刻发生变化。是正确的框被删除了，还是框存在却配错了？是运动预测偏离，还是旧身份在历史更新中被覆盖？将错误定位到这些具体环节，比直接追逐一个更新的模型名称更容易建立理解。

多目标跟踪最终要建立的，是对象在时间中的连续性。画面不断变化，观察时有缺失，而一个可靠的系统需要在这些不完整信息之间，持续维护“它还是它”的判断。
