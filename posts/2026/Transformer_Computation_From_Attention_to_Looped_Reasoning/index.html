Transformer 的算力之争：从堆叠深度到循环推理

2026-10-25

Topic: Transformer Architecture and Recurrent-Depth Reasoning
Keywords: Attention、KV Cache、MoE、Universal Transformer、Looped Transformer、Latent Reasoning

引言：模型要更聪明，除了变大还能做什么？

一道题需要先找出几个条件，再沿着条件推导，最后检查有没有矛盾。一个语言模型可以把这些步骤写出来，也可以在内部表示上多做几轮计算。两种方式都增加了思考的机会，却把计算放在了不同地方。

让模型变强，最直观的办法是增加参数、训练更多数据。但参数决定了模型能够容纳多少可调用的模式，计算步骤则决定了它能怎样加工眼前的信息。记住更多知识，与沿着已有条件多推导几步，是两种不同的需求。

Transformer 的结构演化一直围绕这些需求展开：输入变长，就要重新设计信息如何交流；生成变贵，就要减少历史状态的存储和搬运；模型变大，就要考虑每次调用哪些参数。而当任务需要更多推导步骤时，一个问题随之出现：是否一定要为每一步计算都准备一套新的参数？

Looped Transformer 给出了一种思路：让同一组网络层反复处理不断变化的内部状态。要理解它为什么有用，可以先从一个普通的 Transformer 模块出发，看看信息怎样在位置之间交流，又怎样沿着网络深度逐步加工。

1. 起点：Transformer 把信息交流与特征加工分开

1.1 一个 token 怎样知道应该关注谁？

这两种扩大方式并不等价。一张纸上能同时写更多东西，与允许多做几轮推导，是两种能力。后面的循环深度路线，正是要把“参数容量”和“加工次数”进一步分开。

1.3 BERT、GPT、T5：先改变读写方式

早期 Transformer 家族的一个重要分叉，是不同位置允许看见什么，以及输入和输出如何组织：

Encoder–Decoder T5、原始翻译 Transformer 先编码输入，再由解码器读取编码结果并生成输出

BERT 强调双向上下文，T5 将多种任务统一成文本到文本。这一分叉改变读写接口，并不直接回答后来的长上下文、显存和循环深度问题。它们是技术地图上的不同维度。

2. 输入越来越长：注意力该看谁，怎样看？

2.1 全连接注意力的账单

如果一段输入有 个位置，全注意力需要考虑约 组位置关系。把输入从一千个 token 增加到一万个，关系数量就从百万级增至亿级。

对整段输入的处理，也就是常说的 prefill，标准稠密注意力的核心运算随长度呈平方增长。逐 token 解码时，若已有 KV 缓存，新 token 通常只需与历史做一次注意力，单步开销随历史长度增长；不能把 prefill 的平方成本原样套到每个解码步上。

长上下文路线由此分成几种思路。

2.2 稀疏注意力：先减少连接

Longformer 将局部窗口与少量全局位置结合起来。可以把它想成：大多数位置先与附近交流，关键位置承担远距离联系。

固定窗口和固定全局位置数量时，连接数可以随序列长度近似线性增长。代价是信息交流路径受到限制：原本一跳就能直接读取的远处内容，现在可能需要通过多层或全局节点传递。

这条路线改变的是哪些位置可以互相读取。它省下了部分连接，也需要重新考虑任务是否依赖被删掉的联系。

2.3 线性注意力：重新组织关系计算

Performer 通过随机特征近似 softmax 注意力核，以线性复杂度估计全注意力。它与局部窗口的思路不同：目标仍然是汇总更广泛的信息，但采用更便宜的表示和计算方式。

线性复杂度通常意味着对特征维度等条件作了固定。近似误差、状态容量和真实硬件效率仍然需要检查。一个理论复杂度更低的方法，在短序列或不合适的实现上，也可能跑得更慢。

2.4 FlashAttention：连接照算，数据少搬

FlashAttention 的标准稠密版本保持精确注意力，通过分块和减少 GPU 显存读写提高效率，避免将完整的注意力矩阵反复写回大显存。

它主要优化计算的执行方式。精确在这里指算法目标不采用注意力近似，实际浮点结果仍会受数值精度和计算顺序影响。它没有把稠密注意力的算术复杂度自动变成线性。

把这些方法放在一起，区别就清楚了：稀疏注意力减少连接，线性注意力改变计算表示，FlashAttention 优化数据搬运。它们回答同一个成本问题，却不属于同一种结构变化。

2.5 位置编码与跨段记忆：长输入还有另一半问题

即使算得动，模型也需要理解位置关系。RoFormer 的旋转位置编码 RoPE 将位置信息引入查询和键的旋转，使注意力得分能够表达相对位置关系。它提供一种位置接口，但训练长度之外是否可靠，仍取决于训练与位置扩展方案。

Transformer-XL 则通过跨片段复用历史隐状态扩大可利用的上下文。这里的“循环”沿着文本片段推进：让新片段读到过去。后文的 Looped Transformer 则主要沿计算深度推进：对当前状态反复加工。二者都出现 recurrence 这个词，循环轴却不同。

3. 生成越来越贵：MHA、MQA、GQA 与 MLA 在省什么？

3.1 KV Cache 是已经读过的内容留下的记录

生成下一个 token 时，过去位置的键和值通常可以缓存起来，避免每一步都重新计算。代价是历史越长，缓存越大，读取它的带宽开销也越明显。

3.2 从每个头单独保存，到多个查询头共享

多头注意力（MHA）让不同查询头配有各自的键和值，提供多个信息读取视角。MQA 则让多个查询头共享一组 KV 头，以减少缓存与带宽需求。

GQA 在二者之间折中：将查询头分组，每组共享 KV。查询头依然可以不同，只是它们读取的键值表示部分共享。

MLA（Multi-head Latent Attention）在 DeepSeek-V2 中采用另一种设计：将 KV 的主要内容信息压缩进低维潜在表示，并对位置相关部分作专门处理。缓存不再简单等于“每头保存一份完整 K 和 V”，因此不能只用上面的常规头数公式估算全部开销。

这些设计改变的是历史记录如何存储和读取。它们可以与更深网络、MoE 或循环深度组合，但本身不代表增加了推理步骤。

4. 参数越来越多：MoE 把容量与每步计算部分分开

普通稠密网络每处理一个 token，通常都调用相关层中的整套 FFN 参数。如果希望存储更多知识、容纳更多模式，扩大网络也会增加每步计算。

混合专家（Mixture of Experts，MoE）在一层中提供多组专家网络，通过路由器为 token 选择其中少数几组。Switch Transformer 是简化稀疏专家路由的代表。

可以将它理解为准备了更多可调用的加工模块，但每次只调用其中一部分。总参数量描述系统拥有多少参数，激活参数量描述一次 token 处理实际调用多少，二者因此不再相同。

不过，专家仍要存放在设备上。跨设备通信、路由开销和负载不均都会影响实际速度。激活参数更少，并不能直接推导延迟一定更低。

MoE 扩大的是可选择的参数容量。接下来要讨论的 Looped Transformer 则问：已有的一套参数，能否多用几次？

5. 另一条伏线：从 Universal Transformer 到循环深度

5.1 一套规则，可以执行很多步

求解方程时，我们可以反复使用同一个更新规则，逐步改善当前解。规则没有变化，但每轮输入的状态都在变化，所以输出也会变化。

2018 年公开、发表于 ICLR 2019 的 Universal Transformer 已经沿着深度反复应用共享变换，并探索按位置动态停止计算。这条路线保留注意力的信息交流，同时引入迭代更新的归纳偏置。

ALBERT 也使用跨层参数共享，主要围绕参数效率设计。它说明共享层参数并非新近才出现；但共享参数、动态决定深度和专门训练潜在推理，是三个可以分别选择的设计。

5.3 为什么重复计算不等于原地打转？

因为下一轮处理的是上一轮更新后的状态。第一轮可能建立局部联系，第二轮基于这些联系汇总更远的信息，之后再调整中间表示。这里描述的是可能实现的迭代机制，不意味着每个训练好的模型都会自动形成可命名的步骤。

2025 年的 Reasoning with Latent Thoughts 在合成推理与语言模型实验中研究这一点，并给出与迭代算法相关的理论分析。它支持“某些任务需要较大的计算深度，却不一定需要同等比例增加独立参数”这一方向，不能扩展成任意小模型循环足够多次就能替代任意大模型。

6. 思维链与潜在推理：计算可以沿两条轴增长

6.1 CoT：把中间结果写进序列

Chain-of-Thought（CoT） 让模型生成中间推导步骤，再利用这些步骤继续作答。每生成新的 token，模型就获得新的计算机会，同时也将中间结果写入后续可以读取的上下文。

它不仅增加耗时，也提供一种可读的中间表示。不过，文本推导仍可能出错，写出的解释也不自动等于完整、忠实的内部计算记录。

6.2 Latent Reasoning：保留连续状态继续计算

潜在推理将部分中间计算保留在连续向量中，减少必须解码成文字的步骤。Coconut 将最后的隐藏状态直接作为后续输入表示，探索连续思维链；循环深度模型则可以在共享核心内部反复更新状态。

两者存在联系，但实现位置不同。Coconut 的连续步骤可以推进序列位置，不能据此推断其上下文长度或缓存完全不增长。循环深度则可以在不增加文本位置的情况下增加内部更新次数。二者都仍然消耗计算。

比较维度 显式 CoT 循环深度中的潜在更新
中间状态 生成的文字 token 连续隐藏表示
主要扩展方向 序列继续增长 当前状态的迭代深度增加
下一步依据 原输入与已生成文本 历史信息与更新后的内部状态
成本重点 解码、增长的上下文与缓存 串行迭代、状态与深度缓存
如何理解过程 可以阅读文字，仍需核查忠实性 需要读出、探针或因果干预分析

它们也可以组合：内部先做几轮更新，再写出一段推导，接着继续计算。文本更短可能节约解码和上下文成本，但仅看输出 token 数，无法判断总 FLOPs 或总延迟是否更低。

7. 从概念到语言模型：Huginn 与 Ouro

7.1 Huginn：在输入与输出之间留出可迭代的核心

Scaling up Test-Time Compute with Latent Reasoning 将模型组织为输入侧的 prelude、共享的 recurrent core，以及输出侧的 coda。输入先进入潜在空间，核心反复更新状态，最后再产生输出分布。

其 Huginn 原型达到 3.5B 参数，并使用 800B token 训练。论文研究了增加测试时迭代和提前退出等行为，展示循环深度可以成为推理预算的一部分；这类原型实验仍需要放在具体数据与模型规模中理解。

7.2 Ouro：将循环与深度分配纳入预训练

Ouro / LoopLM 进一步研究大规模预训练中的共享循环和学习式深度分配，公开了 1.4B、2.6B 模型。它将“用现有表示多算几步”与预训练目标结合起来。

这条路线很适合检验一个问题：推理提升究竟来自记住更多事实，还是更好地组合已有事实？重复调用共享参数可以改善加工能力，却不会自动增加独立参数的存储容量。比较时，模型大小、训练数据量和实际计算预算都应记录。

7.3 缓存问题开始浮出水面

一个 token 可以有序列位置 ，也可以有循环轮次 。如果每轮都分别保存历史 K、V，缓存也就多了深度这一轴。

Ouro 论文专门区分 prefill 与 decoding 中的缓存复用实验：前者的不同轮状态不能简单用早期轮替代，后者才进一步探索复用策略。Huginn 也研究了缓存预算和复用方法。它们都表明，缓存共享需要单独设计和验证，不能从“权重相同”直接推导。

8. 从“多算几轮”到“哪些位置值得多算”？

8.1 动态深度：简单位置可以先退出

一句话中的常见连接词与一道数学题的关键数字，可能需要不同的处理深度。若所有位置都执行最大循环数，大量计算可能花在已经足够确定的状态上。

Universal Transformer 的动态停止机制很早就涉及这个问题。后来的 Mixture-of-Depths（MoD） 则在给定层选择部分 token 参与计算，使计算预算在位置之间动态分配。

MoD 本身不要求不同层共享参数。它回答“谁需要经过这一层”，与循环网络回答的“同一核心执行几轮”，可以分别设计。

8.2 MoE、MoD、MoR：三个相似名字，三个路由对象

Mixture-of-Recursions（MoR） 将共享层栈与逐 token 的递归深度路由结合起来，并研究选择性缓存与缓存共享变体。

路线 主要选择什么 与循环深度的关系
MoE 当前 token 调用哪些专家参数 扩大可选参数容量，可与循环组合
MoD 当前层计算哪些 token 分配层内预算，不必共享层参数
MoR 当前 token 经过多少轮共享递归 同时考虑参数复用和深度分配

实际收益还依赖执行方式。如果同一批次中有的 token 需要两轮、有的需要十轮，GPU 可能需要等待、重排或压缩活跃位置。理论上省下的计算，只有被实现有效利用后，才会变成真实速度收益。

8.3 “状态不再变化”不等于“答案已经正确”

提前停止可以参考输出分布、隐藏状态变化或学习到的门控。它们都是停止信号，而非正确性证明。模型可能很快稳定在一个错误状态，也可能在几个状态之间振荡。

2026 年的 Think-at-Hard（TaH） 观察到潜在过度思考：部分第一轮已经正确的 token，继续迭代后反而变错。其方法用轻量决策器选择需要迭代的位置，再配合深度相关适配与跨迭代信息交流。

这使研究问题更加具体：增加循环数只是提供更多计算机会，训练与停止策略还要让这些机会转化为有效更新。

9. 循环之后，怎样教会模型做有用的更新？

只在网络外面加一个循环，并不能保证它获得多步推理能力。训练必须让共享核心在不同状态、不同深度下都能工作。

第一个难点是优化。 同一组参数在展开图中多次使用，反向传播会穿过多轮状态。归一化、初始化、展开步数和梯度截断都会影响稳定性；截断可以控制训练成本，也会改变梯度能够覆盖的范围。

第二个难点是监督。 只监督最后答案，模型需要自行找到中间更新；在各轮或潜在位置施加监督，则可以更明确地约束计算过程，但需要设计对应关系与损失。

2026 年的 LOTUS 将循环骨干与多个潜在块上的并行 CoT token 监督结合起来。它探索的不是取消推导监督，而是把推导信号用来训练连续计算。其结果针对论文的训练与任务条件，不能解释为所有隐藏状态都能被完整翻译成可靠文字。

第三个难点是深度外推。 一个模型训练时习惯少量循环，测试时允许更多轮，不代表它一定持续提升。共享参数让重复执行成为结构上的可能；训练是否学到可延伸的迭代规则，仍需实验回答。

从 Universal Transformer 到 Huginn、Ouro、MoR，再到 LOTUS 与 TaH，这条路线逐渐从“参数可以共享”走向“怎样训练迭代、怎样分配迭代、怎样在合适时刻停止”。这也是循环推理与简单模型压缩之间最重要的区别。

10. Mamba、ViT、Swin、DiT：其他分支在改变什么？

10.1 Mamba 的循环沿时间推进

Mamba 用选择性状态空间模型处理序列，通过随输入变化的状态更新传递或遗忘信息。它是注意力之外的序列建模路线，也可以与注意力构成混合架构。

理解它时，可以分别画出两条轴：时间轴从第一个 token 走向后续 token，深度轴在当前计算状态上做更多变换。Mamba 主要改变沿时间传递信息的机制，Looped Transformer 主要研究共享变换沿深度重复执行。二者可以讨论组合，但不能仅因都含有循环就当成同一种模型。

10.2 视觉分支改变 token、空间结构与任务输出

Transformer 也不只处理文字。视觉模型的主要变化，常常发生在“把什么变成 token”和“怎样组织空间关系”上：

方法 主要改变 与循环深度的区别
ViT 将图像 patch 组织成序列进行表征学习 改变输入单位，不要求重复共享层
Swin 窗口、移位与层级特征 改变空间交流与多尺度组织
DETR 用对象查询和集合预测输出检测结果 改变任务接口与监督方式
DiT 用 Transformer 处理潜在图像 patch，作为扩散模型骨干 去噪步是生成过程的迭代，不自动等于骨干内部的深度循环

同一个 Transformer 去噪网络被多次调用时，每次的噪声状态和时间条件会变化。这与对隐藏状态反复应用共享核心有相通之处，但迭代对象、训练目标和状态语义需要分别说明。

11. 把这些名字放回一张技术地图

这些路线在时间上交叠，也可以组合。下面按首次公开的代表年份标记拐点，年份用于定位，不表示后来的方法全部由前一行直接派生。

时段 代表性变化 打开的设计空间
2017 Transformer 用注意力组织序列内部的信息交流
2018–2019 BERT、Universal Transformer、Transformer-XL、ALBERT、MQA 读写方式、循环共享、跨段记忆与缓存分别成为设计变量
2020–2021 Longformer、Performer、RoPE、Switch Transformer 连接稀疏性、位置表达与专家容量分化
2022–2024 FlashAttention、GQA、MLA、MoD 显存搬运、缓存表示与计算分配深入系统层面
2024–2025 Coconut、循环深度理论、Huginn、MoR、Ouro 从连续思维表示走向可训练的共享迭代与自适应计算
2026 LOTUS、Think-at-Hard 等 进一步处理潜在监督、选择性迭代与过度思考

如果遇到一个新的架构名称，可以先问它改动了哪一项：

  • 交流范围： token 能读取哪些位置？
  • 历史存储： 保留完整 KV、压缩表示，还是递归状态？
  • 参数调用： 每次调用同一套、不同层，还是路由到专家？
  • 计算深度： 固定执行、跳层，还是循环与动态退出？
  • 任务接口： 输入是文本、图像 patch 还是潜在状态，输出又是什么？

这样就能看出，GQA、MoE 和 Looped Transformer 并非天然互斥的候选。它们可以作用于同一系统的不同环节。复杂结构最终是否值得采用，还要看这些环节在硬件上如何配合。

12. 循环推理真正改变的，是计算预算的用法

回到开头那道需要多轮推导的题。扩大参数容量，可以让模型容纳更多可调用的模式；扩大上下文，可以让更多材料进入计算；增加深度或迭代，则让模型有机会继续加工已有信息。这几个方向相关，却不能互相替代。

因此，比较循环模型时至少要分清：是在相同参数量下比较，还是相同训练 FLOPs、相同推理 FLOPs、相同显存或相同延迟下比较？一个小模型循环多次，可能在参数效率上获胜，却未必在速度上获胜。减少可见文字，也可能只是把开销转移到了内部计算。

读一篇相关论文，还应查看循环数增加后的完整曲线，检查是否出现收益饱和或退化；区分 prefill 与 decode，记录缓存是否跨轮共享；同时观察长输入、知识任务与推理任务，而非只挑最适合迭代的例子。

Looped Transformer 带来的一个有价值的转变，是让有效计算深度成为可以研究、训练和调度的资源。模型不再只能依靠增加不同层来获得更多加工步骤，也可以学习反复使用同一套变换。它能否形成可靠、经济的推理能力，最终取决于每一轮是否带来有用信息，以及系统能否把计算花在真正需要的位置。
