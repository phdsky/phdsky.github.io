DVGT-2: Vision-Geometry-Action Model for Autonomous Driving at Scale

2026年04月01日

Task: End-to-End Autonomous Driving with Dense Geometry
Method: Vision-Geometry-Action, Streaming DVGT, Temporal Causal Attention, Historical Cache
Venue: arXiv
Year: 2026
Paper: https://arxiv.org/abs/2604.00813
Code: https://github.com/wzzheng/DVGT

1. 摘要

DVGT-2 提出 Vision-Geometry-Action（VGA） 范式，把 dense 3D geometry 作为自动驾驶决策的重要线索。相较于 DVGT 的 batch 式多帧几何重建，DVGT-2 改成 streaming 结构：用 temporal causal attention、historical feature cache 和 sliding-window streaming strategy 支持在线推理，并联合输出当前帧 dense geometry 与 trajectory planning。

DVGT-2 要解决的缺口很清楚：DVGT 证明 dense geometry 可以从驾驶多相机序列中学出来，但如果它只能离线 batch 推理，就很难进入真实自动驾驶规划链路。DVGT-2 的重点不是再做一张更好的 point map，而是把 dense geometry 变成可在线更新、可被规划 head 使用的中间表示。

核心论点：端到端驾驶不一定只能走 sparse query 或 VLA 路线；dense geometry 也可以成为从 vision 到 action 的中间桥梁。

2. 问题与动机

端到端自动驾驶正在从稀疏感知走向 VLA 等多模态路线，但语言辅助并不能直接提供物理空间约束。DVGT-2 的问题意识是：自动驾驶首先发生在三维空间里，dense 3D geometry 应当进入规划链路；同时，几何重建必须从离线 batch 模式走向在线 streaming 模式。

这背后有两个现实矛盾：

矛盾 说明
语义推理强但物理约束弱 VLA 能理解语言和意图，但不天然提供度量空间结构
几何信息强但在线使用难 dense geometry 提供空间约束，但 batch 重建难以满足实时规划

DVGT-2 试图同时解决这两个问题：保留 geometry 的物理 grounding，同时把模型改造成可在线推理的 driving system。

3. 核心洞察

洞察 1：VGA 是 VLA 的几何对照路线

VLA 借助语言描述辅助规划，VGA 则强调几何结构直接约束决策。两者并不互斥，但 VGA 更贴近物理空间。

可以这样区分：

VLA 更擅长语义解释和指令理解；VGA 更擅长表达空间、距离、遮挡、free space 等物理约束。

洞察 2：在线规划需要 streaming geometry

DVGT 依赖多帧 batch 处理，难以直接接入在线规划。DVGT-2 通过 temporal causal attention 和 historical cache 避免重复计算。

这里的 causal 很关键：在线系统不能看未来帧。Temporal causal attention 保证当前输出只依赖历史信息，historical cache 则让模型复用过去特征，而不是每次重新处理完整窗口。

洞察 3：同一几何模型可以连接重建和规划

DVGT-2 不只输出 point map，也输出 trajectory planning，使 dense geometry 从感知结果变成任务中间表示。

这一步把 geometry 从“看得准”推进到“能不能帮助开车”。如果 dense geometry 不能服务 action，它就只是重建模块；接上 trajectory planning 后，它才真正进入端到端驾驶范式。

定位 driving geometry perception Vision-Geometry-Action driving

DVGT-2 的关键不是否定 DVGT，而是把 DVGT 的 dense geometry 能力改造成可在线服务 action 的系统。

5. 实验与分析

论文报告 DVGT-2 在多数据集上保持更快推理，并可在 closed-loop NAVSIM 和 open-loop nuScenes 上直接用于 planning。关键结论是：dense geometry 可以进入端到端规划，但不意味着所有稀疏 query 系统都会被替代。

实验应按两类证据理解：

证据 说明
Geometry quality / speed streaming DVGT 是否仍能提供可靠几何
Planning evaluation dense geometry 是否能改善 trajectory output

这比单纯重建指标更进一步，因为它检验了几何表示是否真的能穿透到 action 层。

三个关键数字：

  • 3 个字母 VGA：Vision、Geometry、Action。
  • 2 类输出：dense geometry 与 trajectory planning。
  • 2 类规划评估：closed-loop NAVSIM 与 open-loop nuScenes。

6. 工程实践

DVGT-2 的工程重点在 streaming：缓存历史特征、避免未来信息泄漏、控制窗口长度，并处理多相机配置变化。真实系统还需要把规划输出接入车辆动力学、安全约束和闭环评测。

具体落地时要特别关注：

  • cache 生命周期：历史特征太旧会污染当前判断，太短又丢失时序线索；
  • causal 约束：训练时不能无意使用未来帧，否则推理会掉点；
  • 几何到规划的接口：point map 是否转成 cost、query、occupancy 或直接作为 feature；
  • 算力预算：dense geometry 比 sparse query 更重，必须证明它带来的规划收益值得成本。

7. 研究启示

DVGT-2 是 geometry-centric 自动驾驶路线的重要信号：dense geometry 不再只是离线重建指标，而可以成为在线规划中的结构化中间表示。它和 SparseDrive、DiffusionDrive 形成互补关系：前者关注空间结构，后两者分别关注稀疏任务表示和动作分布。

DVGT-2 的真正启示是：自动驾驶端到端路线可能会分化成三种互补表达：

路线 核心表示
Sparse query 任务相关实体和地图元素
Action distribution 多模态轨迹 / 动作分布
Dense geometry 真实尺度 3D 空间结构

DVGT-2 代表第三条路线进入规划层。它不必替代 SparseDrive 或 DiffusionDrive，但它提醒系统设计者：没有可靠的 metric geometry grounding，端到端规划很容易只学到数据分布，而缺少物理约束。
