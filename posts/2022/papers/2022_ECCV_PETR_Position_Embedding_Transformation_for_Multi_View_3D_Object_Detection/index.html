PETR / PETRv2 Position Embedding Transformation for Multi-View 3D Perception

2022年03月10日

Task: Multi-View 3D Object Detection / BEV Segmentation / 3D Lane Detection
Method: 3D Position Embedding, Transformer, Set Prediction, Temporal Alignment, Feature-guided PE
Venue: ECCV 2022 (PETR) / ICCV 2023 (PETRv2)
Year: 2022 / 2023
Paper: https://arxiv.org/abs/2203.05625 (PETR) / https://arxiv.org/abs/2206.01256 (PETRv2)
Code: https://github.com/megvii-research/PETR

摘要

本文提出了位置嵌入变换方法（Position Embedding Transformation, PETR），用于多视图 3D 目标检测。该方法的核心思想是：将 3D 坐标的位置信息编码到 2D 图像特征中，生成 3D 位置感知特征（3D position-aware features）。Object query 可以直接感知这种 3D 位置感知特征，实现端到端的 3D 目标检测。与此前的 DETR3D 需要将 3D 参考点反向投影到图像平面并采样 2D 特征的方式不同，PETR 避免了在线 2D-to-3D 变换和特征采样过程，保持了原始 DETR 的端到端精神。具体来说，PETR 先将相机视锥空间离散化为 3D 网格坐标，再经相机参数变换到 3D 世界坐标系，最后通过简单的 MLP 将 3D 坐标编码为位置嵌入并与 2D 特征融合。在 nuScenes 数据集上，PETR 以 V2-99 Backbone 达到了 50.4% NDS 和 44.1% mAP 的 SOTA 性能，成为首个突破 50% NDS 的纯视觉方法。

核心论点：多视图 3D 检测的关键在于如何让 2D 图像特征”感知”3D 空间——PETR 借鉴隐式神经表示的思想，通过将 3D 坐标编码为位置嵌入注入 2D 特征，实现了从”3D-to-2D 投影采样”到”2D-to-3D 位置编码”的范式转变。

问题与动机

多视图 3D 目标检测旨在从多个相机图像中预测 3D 边界框，是自动驾驶感知系统的核心任务。现有方案可分为三类：

方法类型 代表作 核心问题 NDS（nuScenes val）
单目检测 FCOS3D / PGD 逐视图独立检测，无跨视图推理 0.415 / 0.428
BEV 方法 BEVDet 需要显式深度估计构建 BEV 表示，引入 Z 轴误差 0.417（Swin-T）
3D-to-2D 投影 DETR3D 3D 参考点投影到 2D 采样特征，投影误差和局部采样限制性能 0.434（R101）

DETR3D 作为 DETR 在 3D 检测中的直接扩展，提供了一种端到端方案：object query 生成 3D 参考点 → 投影到图像平面 → 采样 2D 特征。但这一框架存在三个问题：

  1. 投影误差：预测的 3D 参考点不够精确时，采样位置偏离物体区域
  2. 局部特征采样：只收集投影点处的特征，无法利用全局视觉信息
  3. 工程复杂度：在线投影和特征采样流程复杂，不利于实际部署

核心痛点：如何在不进行显式 3D-to-2D 投影和特征采样的前提下，让 Transformer 的 object query 直接感知 3D 空间信息，实现更简洁、更有效的端到端多视图 3D 检测。

核心洞察

洞察 1：3D 位置编码替代 3D-to-2D 投影

传统做法（DETR3D）让 query 先预测 3D 参考点，再投影回图像采样特征——信息流是”3D → 2D”。PETR 反转了这一逻辑：将 3D 坐标信息编码到 2D 特征中，让 2D 特征”升维”到 3D 空间。

DETR3D 做法：object query → 预测 3D 参考点 → 投影到 2D → 采样局部特征 → 更新 query
PETR 做法：相机视锥 → 生成 3D 坐标 → MLP 编码为 3D PE → 与 2D 特征相加 → query 直接交互

洞察 2：隐式神经表示思想赋予 2D 特征 3D 感知能力

PETR 的设计灵感来自隐式神经表示（Implicit Neural Representation, INR）。在 MetaSR 和 LIIF 中，通过将高分辨率坐标编码到低分辨率特征中，可以生成任意尺度的超分辨率图像。PETR 将这一思想迁移到 3D 检测：将 3D 世界坐标编码到 2D 图像特征中，生成 3D 位置感知表示。

传统做法：2D CNN 特征 + 2D 位置编码 → 缺乏 3D 空间感知
PETR 做法：2D CNN 特征 + 3D 位置编码（MLP 编码 3D 坐标）→ 特征具有 3D 空间感知

洞察 3：3D 可学习锚点替代原始 object query

理解 PETR 的 query 设计，需要先回顾 DETR 系列中 query 的演进：

DETR（2D 检测） DETR3D PETR
query 初始化 随机可学习嵌入 nn.Embedding(N, d) 从 query 预测 3D 参考点 3D 可学习锚点 + MLP 编码
空间先验 无（纯抽象 object slot） 有（预测得到） 有（直接在 3D 空间初始化）
如何”找到”目标 cross-attention 在 2D 特征图上软选择 投影到 2D 采样特征 cross-attention 在 3D 位置感知特征上全局交互
位置更新 无（query 固定） 逐层 refine 参考点 回归相对于锚点的偏移

DETR 的 query 本质：DETR 的 query 没有空间坐标，它通过 cross-attention 去图像特征中”找位置”——encoder 特征带有 2D positional encoding，query 通过 attention 权重选择性关注某些空间位置。训练中，Hungarian matching 让某些 query 被反复匹配到特定类型的目标，梯度驱动它们在 cross-attention 中更关注对应区域，最终每个 query 变成一个”会主动在图中找目标的探针”。

PETR 的关键改进：DETR 的纯可学习 query 设计在 2D 检测中表现良好，但将这种无空间先验的 query 初始化方式直接搬到 3D 场景中会导致无法收敛（消融实验中 “None” 不收敛）。具体原因有三：

  • 3D 空间极度稀疏：2D 图像是稠密的（每个像素都有值），query 通过 cross-attention 容易找到物体。而 BEV/3D 空间中物体高度稀疏，尤其远距离区域几乎没有有效特征，无空间先验的 query 难以聚焦
  • 空间尺度跨度巨大：2D 中物体占据数百像素，搜索空间有限。3D 中 x/y 范围可达 ±61.2m、z 范围 ±10m，分辨率 0.1~0.2m，query 需要在一个量级远大于 2D 的空间中定位目标
  • 7-DOF box 优化更困难：3D 检测需要预测 (x, y, z, l, w, h, θ) 共 7 个自由度（加速度则更多），参数空间远大于 2D 的 4-DOF box，Hungarian matching 的匹配空间急剧增大，收敛更加困难

DETR3D 通过让 query 预测 3D 参考点来解决这一问题，但仍依赖逐层投影采样。PETR 则引入 3D 可学习锚点（learned anchor points），在 3D 世界空间中直接初始化均匀分布的锚点坐标，再通过小型 MLP 将其转换为 query embedding，为每个 query 赋予明确的 3D 空间起点——无需投影，query 直接与 3D 位置感知特征交互。

消融实验表明：不使用锚点（DETR 式纯可学习 query）模型不收敛；固定 BEV 网格锚点（39×39）达到 0.337 NDS；固定 3D 网格锚点（16×16×6）达到 0.343 NDS；可学习 3D 锚点达到 0.359 NDS。锚点数量从 600 增加到 1500 时性能持续提升（0.339 → 0.359 NDS），最终选择 900 个作为精度与计算量的折中。

三个关键数字：

  • 50.4% NDS：PETR（V2-99）在 nuScenes test 上达到的 SOTA，首个突破 50% NDS 的纯视觉方法
  • 30.5% mAP：仅用 3D PE（无 2D PE / 多视图先验）即可达到的性能，证明 3D PE 的核心作用
  • 10.7 FPS：PETR（R50, 1056×384）的推理速度，同分辨率下 BEVDet 仅 4.2 FPS（在更强的 3090 上）

性能瓶颈分析

PETR 的主要性能瓶颈在于：

  • 收敛速度较慢：与 DETR3D 对比，PETR 在前 12 epochs 内收敛慢于 DETR3D，需要更长训练周期才能发挥全部潜力。作者推测原因是 PETR 通过全局注意力学习 3D 相关性，而 DETR3D 在局部区域感知 3D 场景
  • 定位精度（mATE）偏高：PETR（R101）的 mATE 为 0.711，高于 BEVDet 的显式深度估计方案。由于 3D PE 隐式编码深度，缺乏显式深度监督可能导致定位不够精确
  • 小物体检测不足：论文 Figure 8 失效案例分析中，红色圆圈标注了未检出的小物体，这与隐式深度表示在远距离小物体上的不确定性有关

失效场景分析

  • 小物体漏检：论文 Figure 8 明确展示了远距离小物体（如远处行人）未被检测到的情况，3D PE 在大深度范围内的分辨率不足是主要原因
  • 外观相似物体误分类：论文 Figure 8 中绿色圆圈标注了被错误分类的物体，不同类型车辆在外观上高度相似时，模型容易混淆类别
  • 隐式深度表示的局限：论文对比表明 PGD 通过显式深度监督获得更低的 mATE（0.683 vs 0.711），PETR 的隐式深度编码方式在精确定位方面存在先天不足

工程实践

训练配置

复现要点

  1. Backbone 学习率分离：backbone 学习率为 transformer 的 1/10（lr_mult=0.1），使预训练特征提取器不被大幅扰动。

  2. 3D PE 网络必须用 1×1 卷积：使用 3×3 卷积会破坏 2D 像素与 3D 坐标的逐点对应关系，导致模型完全不收敛（mAP 降至 0.0%）。

  3. 深度离散化选择：LID（线性递增离散化）和 UD（均匀离散化）性能接近，但 LID 在近距离有更密集的采样，更适合自动驾驶场景。默认 64 个深度 bin。

  4. RoI 范围设置： 表现最佳。Z 轴范围过小（如 ）会限制高度方向的检测能力。

  5. Query 数量和锚点数量一致：代码中 num_query=900，对应 reference_points = nn.Embedding(900, 3)。论文消融显示 1500 个 query 性能更好，但 900 是精度和速度的折中。

  6. CBGS（Class-Balanced Grouping and Sampling）：val set 的主要对比实验使用了 CBGS 策略来缓解类别不平衡，消融实验未使用 CBGS。两者不可直接对比。

  7. GridMask 数据增强：训练中使用 GridMask 遮挡增强，有助于提升模型鲁棒性。

  8. 辅助解码损失：每个解码器层都有独立的分类/回归分支产生预测和损失，有助于中间层学习更好的表示。

  9. IDA 与 BDA 双重数据增强：PETR 代码体系中使用两类数据增强——IDA（Image Data Augmentation）作用在图像 2D 平面（resize、crop、flip 等），会改变 2D 像素坐标，需同步更新相机投影矩阵；BDA（BEV Data Augmentation）作用在 BEV/3D 空间（绕 z 轴旋转、缩放、平移等），图像本身不变，但 BDA 变换矩阵会同时施加到 3D 坐标生成器的变换矩阵（修改 img2lidar）和 3D GT box 上，从而保证模型预测空间与监督目标一致。这使模型学会对 3D 坐标系的旋转/缩放不变，提升几何泛化能力。

性能优化方向

精度提升：

  • 引入时序信息：利用前序帧的特征实现时序融合，PETRv2 通过 3D PE 对齐不同帧的物体位置，在时序建模上显著提升性能
  • 显式深度监督：结合深度估计损失来约束 3D PE 学习更准确的深度表示，可改善 mATE
  • 特征引导的位置编码：PETRv2 进一步引入 feature-guided position encoder，提升 3D PE 的数据自适应能力
  • 多尺度特征融合：使用更高分辨率的特征图来改善小物体检测

速度优化：

  • 3D PE 离线计算：相机参数固定时，3D 坐标变换可离线完成作为额外输入，减少在线计算开销
  • 减少 query 数量：在物体稀疏场景下减少锚点数量以降低解码器计算量
  • 注意力实现优化：PETR 系列实践中，直接替换为 Deformable Attention 往往难以获得稳定的精度/速度双提升，且部署链路更复杂；更常见的工程路线是保留 Global Attention，并结合 Flash Attention 降低显存开销和提升吞吐

研究启示

可迁移的思想

  1. “坐标编码”替代”投影采样”
    PETR 证明了将坐标系信息编码为位置嵌入并注入特征，可以替代显式的几何投影和特征采样。这一思想可迁移至 3D 语义分割（Mask2Former-3D）、占用网络（Occupancy Networks）等需要 2D-3D 关联的任务。

  2. 隐式神经表示思想在检测中的应用
    从 NeRF/LIIF 借鉴的”用坐标编码丰富特征表示”思路，为视觉检测任务提供了新的特征增强范式。类似思想可用于其他需要空间感知的任务，如点云语义分割中编码点坐标。

  3. 3D 可学习锚点提供收敛保障
    在 3D 场景中，原始 DETR 的纯可学习 query 无法收敛，而 3D 锚点提供了必要的空间先验。这启发了后续工作（如 StreamPETR）在锚点设计上的进一步优化。

  4. 仅解码器架构的简洁性
    PETR 去除了 Transformer 编码器，将 3D 空间编码的工作完全交给位置编码，保持了架构的简洁性。这表明在位置信息充分编码的前提下，编码器并非必须。

方法局限

  • 收敛速度慢于 DETR3D：全局注意力方式学习 3D 相关性需要更长训练周期，前 12 epochs 性能低于 DETR3D
  • 缺乏显式深度监督：隐式 3D PE 在精确定位（mATE）上弱于使用显式深度估计的方法（如 PGD、BEVDet）
  • 单帧检测无时序信息：PETR 仅使用当前帧，无法利用时序一致性来改善速度估计（mAVE 较高）

技术影响

  • 开创 3D PE 编码范式：PETR 提出的”将 3D 坐标编码为位置嵌入”的范式被后续大量工作采用，形成了与 BEV 方法并行的 3D 检测路线。该范式在矢量化表征任务（障碍物检测、车道线检测、矢量化地图构建、End-to-End 方案）上优势明显，但在 Dense 预测任务（BEV Seg、Occupancy）上仍不及 BEV 方法
  • 催生丰富的研究生态：以 PETR 为基础衍生了多个研究方向——室外 3D 检测（PETRv2, ICCV 2023；StreamPETR, ICCV 2023；CAPE, CVPR 2023；3DPPE, arXiv 2022；Far3D, AAAI 2024）、多模态融合（CMT, CVPR 2023）、目标跟踪（PFTrack, ICCV 2023；StreamPETR, ICCV 2023）、3D 车道线与拓扑推理（TopoMLP, NeurIPS 2023）
  • 统一 3D 感知框架：PETRv2 在 PETR 基础上扩展为统一的多任务框架，同时支持 3D 检测、BEV 分割和 3D 车道线检测，并在 CVPR 2023 Workshop 获得第一名
  • 推动端到端 3D 检测：PETR 保持了 DETR 的端到端特性，避免了 NMS 等后处理，其 NMS-Free 解码器被 StreamPETR（63.6% NDS、55.0% mAP）等后续工作继续沿用
  • 工业落地价值：PETR 的 3D PE 可离线计算的特性使其在部署时更为高效，GitHub 获超 1k stars，被广泛用作多视图 3D 检测的基线方法

PETR 系列常见问题解答

  1. 为什么坚持用 Global Attention，而不用 Deformable Attention？
    在 PETR 系列的经验中，Deformable Attention 通常不会带来显著且稳定的精度/速度收益，反而会增加部署复杂度。Global Attention 对 3D 车道线、拓扑关系等需要大感受野的任务更友好；同时可以通过 Flash Attention 显著降低显存消耗，具备较好的工程可扩展性。

  2. 为什么要在射线采点来做 3D PE？
    射线采点并非必须条件，更准确地说它是 PETR 在“未引入显式深度估计分支”时的工程选择。替代路线包括：仅使用射线方向向量做位置建模（如 VEDet, CVPR 2023），或先进行深度估计再做点级编码（如 3DDPE, ICCV 2023）。

  3. Sparse query 表征相比 BEV 方法的优势是什么？
    Sparse query 的计算复杂度通常更可控，尤其在远距离检测时不直接随 BEV 网格范围线性膨胀；对 3D 目标检测、3D 车道线等稀疏目标建模更自然，也更容易为车道线等任务提供大感受野。其不足是：在预定义类别上的时序建模效率较高，但面向 open-world 任务时，时序建模与类别外泛化仍更具挑战。

PETRv2：统一多任务 3D 感知框架

论文：PETRv2: A Unified Framework for 3D Perception from Multi-Camera Images（ICCV 2023，同一 Megvii 团队：刘英飞、严俊杰等）

PETRv2 在 PETR 基础上进行三项关键扩展：时序建模（通过 3D PE 坐标对齐实现跨帧融合）、Feature-guided Position Encoder（数据驱动的自适应 3D PE）、以及多任务统一框架（引入任务特定 query 支持 BEV 分割和 3D 车道线检测）。

PETRv2 核心改进

改进 1：3D 坐标对齐实现时序融合

PETR 的一个关键局限是仅使用单帧信息，导致速度估计能力几乎为零（mAVE 0.808 m/s）。PETRv2 通过一种极其简洁的方式引入时序信息——直接对齐不同帧的 3D 坐标。

传统做法（BEVDet4D、BEVFormer）：在 BEV 特征空间中做显式特征对齐（插值变换），受 BEV 分辨率限制
PETRv2 做法：对前一帧的 3D 坐标做 pose 变换到当前帧坐标系，再将两帧的 2D 特征和 3D 坐标沿 batch 维拼接

改进 2：Feature-guided Position Encoder（FPE）

PETR 的 3D PE 完全由 3D 坐标生成，与输入图像内容无关——同一相机的所有帧共享完全相同的 3D PE。这限制了 3D PE 的数据自适应能力。

为什么更优：图像特征隐含了深度线索（如纹理梯度、物体尺度等），FPE 使 3D PE 能根据图像内容自适应调整，相当于隐式引入了视觉深度先验。消融实验显示 FPE 在 PETR 基线上提升 1.5% NDS，在 PETRv2（含时序）上提升 0.8% mAP。此外 FPE 改善了对外参噪声的鲁棒性—— 时 PETRv2 仅降 4.12% mAP，PETR 降 6.33%。

改进 3：任务特定 Query 实现多任务统一

BEVFormer 通过 BEV 栅格 query 支持多任务，但 60,000+ 个 dense query 与 PETR 的 global attention 不兼容。PETRv2 采用稀疏任务特定 query：

  • Det Query（900~1500 个）：可学习 3D 锚点，沿用 PETR 设计
  • Seg Query（625 个）：BEV 空间 patch 锚点，每个对应 25×25 的 BEV 区域
  • Lane Query（100 个）：3D 锚点线，每条由沿 Y 轴均匀采样的 个 3D 坐标组成

三类 query 共享同一个 Transformer Decoder，通过相同的 cross-attention 与 3D position-aware 特征交互，更新后分别送入各自任务头。
